# FutureMart Website Analytics Data Warehouse Schema

## Overview

This document defines the analytical data warehouse schema designed for FutureMart's website activity monitoring platform.

The schema follows a star schema design and supports reporting, user behavior analytics, website performance monitoring, customer engagement analysis, and business intelligence dashboards.

The solution was designed as part of the FutureMart enterprise architecture initiative following the merger of FashionMart and TrendyThreads.

## 1. Objective

Create a data warehouse schema for FutureMart's website activity monitoring system that aggregates daily user activity data for analytics purposes using the Star Schema.

The schema stores daily aggregated user activity data for analytics and reporting, including sessions, page views, actions, engagement, and user behavior metrics.

## 2. Tables Overview (Star Schema)

Fact Table:

* FactDailyWebsiteActivity: Stores daily aggregated website activity metrics such as total sessions, page views, actions, purchases, cart additions, searches, and total engagement duration.

Dimension Tables:

* DimDate: Stores calendar details for daily reporting.
* DimUser: Stores user information for registered and guest users.
* DimPage: Stores website page or URL information.
* DimActionType: Stores action categories such as AddToCart, Purchase, Search, Login, and Logout.
* DimDevice: Stores user agent and device-related information.

## 3. SQL: CREATE TABLE Statements

CREATE TABLE DimDate (
DateKey INT PRIMARY KEY,
FullDate DATE NOT NULL,
DayOfMonth INT,
MonthNumber INT,
MonthName VARCHAR(20),
QuarterNumber INT,
YearNumber INT
);

CREATE TABLE DimUser (
UserKey INT PRIMARY KEY,
UserID INT,
Email VARCHAR(100),
FirstName VARCHAR(50),
LastName VARCHAR(50),
UserType VARCHAR(20)
);

CREATE TABLE DimPage (
PageKey INT PRIMARY KEY,
URL VARCHAR(500),
PageCategory VARCHAR(100)
);

CREATE TABLE DimActionType (
ActionTypeKey INT PRIMARY KEY,
ActionType VARCHAR(50),
ActionCategory VARCHAR(100)
);

CREATE TABLE DimDevice (
DeviceKey INT PRIMARY KEY,
UserAgent VARCHAR(255),
DeviceType VARCHAR(50),
Browser VARCHAR(50),
OperatingSystem VARCHAR(50)
);

CREATE TABLE FactDailyWebsiteActivity (
ActivityFactID INT PRIMARY KEY,
DateKey INT,
UserKey INT,
PageKey INT,
ActionTypeKey INT,
DeviceKey INT,
TotalSessions INT,
TotalPageViews INT,
TotalActions INT,
TotalPurchases INT,
TotalAddToCart INT,
TotalSearches INT,
TotalDurationSeconds INT,
AverageDurationSeconds DECIMAL(10,2),
FOREIGN KEY (DateKey) REFERENCES DimDate(DateKey),
FOREIGN KEY (UserKey) REFERENCES DimUser(UserKey),
FOREIGN KEY (PageKey) REFERENCES DimPage(PageKey),
FOREIGN KEY (ActionTypeKey) REFERENCES DimActionType(ActionTypeKey),
FOREIGN KEY (DeviceKey) REFERENCES DimDevice(DeviceKey)
);

## 4. Design Assumptions / Notes

* The schema follows a star schema design with one central fact table and multiple dimension tables.
* FactDailyWebsiteActivity stores daily aggregated metrics instead of raw event-level data.
* DateKey supports daily analytical reporting and time-based filtering.
* UserKey supports analysis by registered users and guest users.
* PageKey supports reporting by visited page or URL.
* ActionTypeKey supports analysis of user behavior such as purchases, searches, logins, and cart actions.
* DeviceKey supports analysis by browser, operating system, and device type.
* The design is optimized for reporting, dashboards, and daily website activity analytics.
* Source OLTP tables such as Users, Sessions, PageViews, and Actions can be used to populate this warehouse schema.
